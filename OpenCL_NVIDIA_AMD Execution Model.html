從 Work-item 到 SM

同一個 OpenCL kernel，在 NVIDIA 叫 thread / warp / SM，在 AMD 叫 work-item / wavefront / CU。下面的動畫把一次 clEnqueueNDRangeKernel 從切 work-group、派送、切 sub-group、到 lane 真正執行，一步步畫出來。切換上方硬體可以比較兩家的差別。

id 怎麼算

硬體只給 group id 和 local id，其餘都是編譯器算出來的。多維 work-group 會先攤平成 linear local id，再每 32 / 64 個切一個 sub-group。

// OpenCL
size_t gid = get_global_id(0);     // = get_group_id(0) * get_local_size(0) + get_local_id(0) + global_offset
uint   sg  = get_sub_group_id();   // = linear_lid / sub_group_size
uint   ln  = get_sub_group_local_id(); // = linear_lid % sub_group_size

// 2D work-group：linear_lid = lid.x + lid.y * Lx   (+ lid.z * Lx * Ly)
// 16×16 的 WG：warp 0 = y 為 0、1 的兩列；wave64 0 = y 為 0..3 的四列
// → 讓 x 方向連續存取 global memory，同一個 sub-group 的 load 才會合併 (coalesce)

// CUDA
int gid  = blockIdx.x * blockDim.x + threadIdx.x;
int warp = threadIdx.x / 32, lane = threadIdx.x % 32;

// HIP on AMD
int wave = threadIdx.x / warpSize;  // warpSize = 64 on GCN/CDNA, 通常 32 on RDNA

Occupancy：一個 SM / CU 能同時放幾個 work-group

第 2、4 步看到的「放不下就排隊」和「沒別的 warp 可換就閒置」，都由這個計算決定。同一組 kernel 參數，左右比較 A100（sm_80）和 MI50（GCN5, gfx906）。

NVIDIA A100AMD MI50

簡化模型：NV 依 sm_80 規則（每 warp 暫存器以 256 為單位配置、每 block 保留 1 KB shared memory、最多 64 warps / 32 blocks）。AMD 依 GCN 規則（VGPR 以 4 為單位、每 SIMD 最多 10 waves、LDS 以 512 B 為單位、每 CU 最多 16 個多-wave work-group），未計 SGPR 上限。真實數字用 nvcc -Xptxas -v 或 clang 的 -Rpass-analysis=kernel-resource-usage 看。

幾個容易踩的底層細節

warp size 不是 OpenCL 保證的
不要寫死 32。用 get_sub_group_size()，或 host 端查 CL_KERNEL_PREFERRED_WORK_GROUP_SIZE_MULTIPLE：NV 回 32、GCN 回 64。local size 取它的倍數。
load 不會讓 warp 停下來
停住的是下一條用到結果的指令。NV 靠 scoreboard，AMD 靠編譯器插的 s_waitcnt vmcnt(N)。所以 compiler 會把 load 往前排，拉開和 use 的距離。
Independent Thread Scheduling
Volta 之後每個 thread 有自己的 PC，divergent 路徑可以交錯，但同一時刻一個 warp 仍只跑一條路徑。舊程式碼假設 warp 隱式同步會壞，要改用 __syncwarp 和 *_sync intrinsics。
scalar vs vector 是 divergence analysis 決定的
編譯器證明某值在整個 sub-group 都相同，AMD 就放 SGPR 用 s_ 指令算，NV（Turing+）放 UR 暫存器。證明不了就只能放 VGPR，每條 lane 各存一份。
coalescing 以 sub-group 為單位
一個 warp 讀 32 個連續 float = 128 B = 4 個 32 B sector；一個 wave64 讀 256 B。lane 的位址越散，拆成的 transaction 越多。
RDNA 不是 GCN
SIMD32 一個 cycle 跑完一條 wave32 指令，沒有 4-cycle cadence。兩個 CU 組成 WGP 共用 LDS，所以 WGP mode 下一個 work-group 可以跨兩個 CU。
