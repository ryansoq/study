OpenCL → NVIDIA · AMD · PowerVR · Mali 執行模型

從 Work-item 到 SM

同一個 OpenCL kernel 在四家 GPU 上的叫法都不一樣：NVIDIA 是 thread / warp / SM，AMD 是 work-item / wavefront / CU，PowerVR 是 instance / task / USC，Mali 是 thread / warp / shader core。下面的動畫從 clEnqueueNDRangeKernel 開始，依序畫出切 work-group、派送、切 sub-group、lane 真正執行。切換上方的硬體，可以比較四家的差別。

名詞對照

OpenCL 的名稱是抽象層，右邊四欄是它實際對應到的硬體。最重要的是 sub-group 那一列：warp、wavefront、task 都是 SIMT 真正的執行單位，只是四家的寬度從 16 到 128 都有。

id 怎麼算

硬體只提供 group id 和 local id，其他 id 都由編譯器算出來。多維 work-group 會先攤平成 linear local id，再依 sub-group 寬度（16、32、64 或 128）切開。

// OpenCL
size_t gid = get_global_id(0);     // = get_group_id(0) * get_local_size(0) + get_local_id(0) + global_offset
uint   sg  = get_sub_group_id();   // = linear_lid / sub_group_size
uint   ln  = get_sub_group_local_id(); // = linear_lid % sub_group_size

// 2D work-group：linear_lid = lid.x + lid.y * Lx   (+ lid.z * Lx * Ly)
// 16×16 的 WG：Mali warp 0 = y 為 0 的一列；NV warp 0 = y 為 0、1 的兩列；AMD wave64 0 = y 為 0..3 的四列
// → 讓 x 方向連續存取 global memory，同一個 sub-group 的 load 才會合併 (coalesce)

// CUDA
int gid  = blockIdx.x * blockDim.x + threadIdx.x;
int warp = threadIdx.x / 32, lane = threadIdx.x % 32;

// HIP on AMD
int wave = threadIdx.x / warpSize;  // warpSize = 64 on GCN/CDNA, 通常 32 on RDNA

// PowerVR：barrier + 非編譯期 local size → 一個 task 只放一個 WG。固定 local size 可避免浪費
__kernel __attribute__((reqd_work_group_size(128, 1, 1)))
void k(__global float *in, __global float *out) { ... }

Occupancy：一個核心能同時放幾個 work-group

第 2、4 步看到的兩種情況（放不下就排隊、沒有別的 sub-group 可以換就閒置）都由這個計算決定。同一組 kernel 參數下，比較 A100、MI50、PowerVR Rogue（Type 1）和 Mali-G710 四顆 GPU。

NVIDIA A100AMD MI50PowerVR RogueMali-G710

這是簡化模型，各家假設如下。 NV 依 sm_80：每 warp 暫存器以 256 為單位配置，每 block 保留 1 KB shared memory，最多 64 warps / 32 blocks。 AMD 依 GCN：VGPR 以 4 為單位，每 SIMD 最多 10 waves，LDS 以 512 B 為單位，未計 SGPR。 PowerVR 依 Imagination compute 指南的 Rogue 數字：Unified Store 每 USC 20480 個 32-bit 暫存器；resident task 上限假設 48（文件寫「通常 48 以上」），Common Store 容量依配置所以不列入。 Mali 依 Arm 規格表：G710 每 core 2048 threads，暫存器超過 32 個減半成 1024，超過 64 個會 spill；local memory 不佔 on-chip 資源，上限依 OpenCL 回報的 32 KB 計。 真實數字以 driver 和編譯器回報為準。

幾個容易踩的底層細節

sub-group 寬度不是 OpenCL 保證的
四家分別是 16、32、64、128，不要寫死。用 get_sub_group_size()，或在 host 端查 CL_KERNEL_PREFERRED_WORK_GROUP_SIZE_MULTIPLE，local size 取它的倍數。
load 不會讓 warp 停下來
停住的是下一條用到結果的指令。NV 靠 scoreboard，AMD 靠編譯器插入的 s_waitcnt vmcnt(N)，PowerVR 是由 FGS 把等資料的 task 換出去。所以編譯器會把 load 往前排，拉開 load 和使用之間的距離。
PowerVR：barrier 會影響 task 怎麼包
local size 是 32 的倍數時，task 剛好填滿。local size 是 4、8、16 時，一個 task 可以塞好幾個 WG。但 kernel 有 barrier、local size 又沒在編譯期固定時，一個 task 只會放一個 WG，空著的 instance 直接浪費。解法是用 reqd_work_group_size。
Mali：__local 不在 chip 上
Mali 沒有專用的 shared memory，__local 是系統記憶體，經過 load/store cache 存取。在 NV、AMD 上常見的「先搬進 local 再算」tiling 手法，在 Mali 上往往沒有幫助。另外暫存器要壓在 32 個以內，才能跑滿 2048 threads。
scalar vs vector 是 divergence analysis 決定的
編譯器能證明某個值在整個 sub-group 都相同，就放進 scalar 暫存器：AMD 用 SGPR，NV 用 UR，PowerVR 用 shared registers。證明不了就只能放在每條 lane 各一份的 vector 暫存器。
Independent Thread Scheduling
Volta 之後，NV 每個 thread 有自己的 PC，divergent 路徑可以交錯執行，但同一時刻一個 warp 仍只跑一條路徑。假設 warp 會隱式同步的舊程式碼會壞掉，要改用 __syncwarp 和 *_sync 系列 intrinsics。
coalescing 以 sub-group 為單位
一個 warp 讀 32 個連續 float，就是 128 B，等於 4 個 32 B sector；wave64 是 256 B。PowerVR 的 cache line 是 128 B，對應到 64 B 對齊的記憶體區段。lane 的位址越分散，會拆成越多次 transaction。
寬度越小，divergence 越便宜
sub-group 越窄，同一組 lane 走不同分支的機率越低。所以 Mali 的 16-wide 對分支多的 kernel 比較寬容，PowerVR Type 2–4 的 128-wide task 則最怕 divergence。RDNA 改回 wave32，也有一部分是這個原因。
